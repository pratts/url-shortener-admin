# TidyLnk Admin

The admin panel for **TidyLnk**, a URL shortener. Users register, log in,
create short links, change where a link points, delete links, download QR
codes, and manage their profile.

This repo is only the browser UI. The API is the Go backend in
[`pratts/url-shortener`](https://github.com/pratts/url-shortener); its contract
is documented in [`docs/API.md`](docs/API.md), with schemas in
[`docs/openapi.json`](docs/openapi.json).

## Stack

- [Vite](https://vite.dev) + React + TypeScript (strict)
- [shadcn/ui](https://ui.shadcn.com) (Tailwind CSS, Radix) and Lucide icons
- React Router, TanStack Query, React Hook Form + Zod
- A small `fetch` wrapper, with API types generated by `openapi-typescript`
- Vitest, Testing Library and MSW for tests
- Deployed to Vercel as a static SPA

## Getting started

Requires Node.js 20.19+ or 22.12+, and the backend running locally.

```bash
npm install
cp .env.example .env   # then adjust if your backend runs elsewhere
npm run dev            # http://localhost:5173
```

| Variable | Example | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8086/api/v1` | API base URL. Required; the app refuses to start without it. |
| `VITE_SHORT_URL_HOST` | `localhost:8085` | Host of the redirect service, so targets can't point back at a short link. |

`VITE_*` values are compiled into the public bundle; never put secrets in them.

The backend must allow the panel's origin in `CORS_ORIGINS`, e.g.
`http://localhost:5173` in development and `https://admin.tidylnk.com` in
production.

## Project layout

```
src/
├── api/          # fetch wrapper (client.ts) and endpoint functions
├── components/   # app components; ui/ holds the shadcn components
├── hooks/        # TanStack Query hooks for auth, the user and links
├── lib/          # token storage, session handling, Zod schemas, helpers
├── pages/        # Login, Register, Urls, Profile, NotFound (+ tests)
├── test/         # MSW server, fixtures and the test harness
├── types/api.ts  # generated; don't edit
├── routes.tsx    # routes and the auth guard
└── main.tsx
```

## Updating the API types

After a backend API change, regenerate `docs/openapi.json` and the types as
described in [`docs/API.md`](docs/API.md#updating-openapijson):

```bash
npx swagger2openapi@7.0.8 ../url-shortener/docs/swagger.json -o docs/openapi.json
node scripts/fix-openapi.mjs docs/openapi.json
npm run gen:api
```

Then fix any type errors and commit `src/types/api.ts`. CI fails if the
committed types don't match `docs/openapi.json`.

## Deployment

The app deploys to Vercel. [`vercel.json`](vercel.json) rewrites every path to
`index.html` and sets the security headers, including a Content-Security-Policy
whose `connect-src` must list the API origin (currently
`https://api.tidylnk.com`; update it if the API moves).

Set `VITE_API_BASE_URL` and `VITE_SHORT_URL_HOST` in the Vercel project
settings. Preview deployments call whichever API those variables point to, and
that API's `CORS_ORIGINS` must include the preview origin.

## Security notes

- Passwords are sent to the API as typed, over HTTPS; the backend hashes them.
- The session token lives in `sessionStorage` and is dropped when it expires,
  when the API returns 401, or on logout. There is no refresh token.
- Server text is never rendered as HTML, and only `http(s)` targets are
  rendered as links.
